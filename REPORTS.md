# FlawTrack Vulnerability Reporting System Documentation

## Overview

FlawTrack provides an enterprise-grade reporting engine built with **PDFKit** and **json2csv** for streaming export of vulnerability assessments, executive summaries, and SLA compliance audits. Headless browser runtimes (Puppeteer, Playwright) are deliberately avoided to maintain full compatibility with containerized and cloud free tiers (e.g., Render, Railway, Vercel).

All report generation requests are strictly authenticated, role-governed, stream directly to the HTTP client, and trigger an immutable audit event (`AUDIT_ACTIONS.REPORT_GENERATED`).

## Report Endpoints & API Reference

### 1. Single Vulnerability Report
- **Route**: `GET /api/reports/vulnerability/:id` (alias `/api/v1/reports/vulnerability/:id`)
- **Authorization**:
  - `ADMIN`, `ANALYST`, `DEVELOPER`: Full access to any vulnerability report.
  - `REPORTER`: Restricted to vulnerabilities submitted by that reporter (`403 Forbidden` on unauthorized IDOR access).
- **Supported Formats**:
  - `?format=pdf` (Default): High-fidelity, publication-ready PDF document with vectors and data tables.
  - `?format=json`: Structured JSON document containing complete vulnerability state, risk calculations, and audit history.
  - `?format=csv`: Flat tabular representation suitable for SIEM, Excel, and ticketing imports.

#### Data Schema & Content Elements:
1. **Header & Metadata**:
   - Organization banner: `FLAWTRACK CYBERSECURITY INTELLIGENCE PLATFORM`
   - Unique Report ID (`FLAWTRACK-RPT-<ID>`), Generation Date/Time (UTC), Generated By (User & Role).
   - "STRICTLY CONFIDENTIAL" classification banner with dynamic running footer (`Page X of Y`).
2. **Executive Overview**:
   - Title, Lifecycle Status (15-stage state machine), Priority Tier (`P1`, `P2`, `P3`, `P4`).
   - Standard Identifiers: CVE ID (`CVE-YYYY-XXXXX`), CWE ID (`CWE-XXX`), Discovery Source.
3. **Threat & Vulnerability Scoring**:
   - CVSS Base Score (0.0 – 10.0), Severity Rating, Full CVSS v3.1 Vector String.
   - EPSS Score (0.00% – 100.00%) with Percentile Rank.
   - CISA Known Exploited Vulnerability (KEV) flag and Date Added.
4. **Asset Criticality & Exposure**:
   - Asset Name, Type, Environment (`production`, `staging`, `development`, `test`).
   - Business Criticality Rating (1 to 5), Data Sensitivity Rating (1 to 5), Internet-Facing status.
5. **FlawTrack Composite Risk Engine Breakdown**:
   - Composite Risk Score:
     $$\text{Risk} = 100 \times (0.30 \times \frac{\text{CVSS}}{10} + 0.20 \times \text{EPSS} + 0.20 \times \text{KEV} + 0.15 \times \text{Asset} + 0.10 \times \text{Business} + 0.05 \times \text{Exposure})$$
   - Critical Overrides Applied:
     - KEV Active + Internet-Facing $\rightarrow$ Forced `P1` (Critical)
     - CVSS $\ge 9.0$ $\rightarrow$ Minimum `P2` (High)
   - Per-factor breakdown table with weights, normalized scores, and contribution points.
6. **Detailed Technical Findings**:
   - Vulnerability Description & Technical Narrative.
   - Step-by-Step Reproduction Procedure.
   - Business & Technical Impact Assessment.
   - Engineering Remediation Guidance & Action Plan.
7. **NLP Duplicate Detection Correlation**:
   - Stemmed TF Cosine Similarity scores ($threshold \ge 0.70$).
   - Linked Duplicate Parent/Child identifiers and resolutions.
8. **Service Level Agreement (SLA) Status**:
   - SLA Tier Duration: `P1` (24h), `P2` (72h), `P3` (168h / 7d), `P4` (720h / 30d).
   - SLA Target Deadline, Time Remaining or Breach Duration, Warning State (triggered at 75% elapsed).
9. **Status Transition & Audit Timeline**:
   - Complete historical transition logs extracted from the append-only `AuditLog` collection.
   - Timestamps, actors, action types, and state change transitions.
10. **Evidence & Attachments**:
    - List of uploaded artifacts, MIME types, file sizes, and remote Cloudinary URLs.

### 2. Executive Summary Report
- **Route**: `GET /api/reports/summary` (alias `/api/v1/reports/summary`)
- **Authorization**: `ADMIN`, `ANALYST`, `DEVELOPER`
- **Query Filters**:
  - `format`: `pdf` (default) | `csv`
  - `from`: ISO Date (`YYYY-MM-DD`) filter start
  - `to`: ISO Date (`YYYY-MM-DD`) filter end
  - `status`: Filter by lifecycle state (e.g., `IN_PROGRESS`, `SUBMITTED`, `CLOSED`)
  - `priority`: Filter by priority tier (`P1`, `P2`, `P3`, `P4`)

#### Data Schema & Content Elements:
1. **Portfolio KPI Metrics**:
   - Total Tracked Vulnerabilities.
   - Active Triage vs. Remediated & Closed Count.
   - Portfolio SLA Compliance Percentage.
   - Total Number of SLA-Breached Items.
2. **Distribution Breakdowns**:
   - Count by Priority Tier (`P1` Critical, `P2` High, `P3` Medium, `P4` Low).
   - Count by Lifecycle Status (15 statuses mapped).
3. **Native Vector Visualizations (PDFKit Native Bar Charts)**:
   - Priority Distribution Bar Chart rendered with vector polygons and custom HSL color tokens.
4. **Top 10 Critical Risks Table**:
   - Ranked list by FlawTrack Risk Score, CVE ID, Asset, Due Date, and Assignee.
5. **CVSS vs. FlawTrack Contextual Tier Comparison**:
   - Highlights discrepancies where pure CVSS overestimates (e.g. CVSS 9.8 on an isolated test server downgraded to P3) or underestimates risk (e.g. CVSS 6.5 with active KEV on an internet-facing production gateway escalated to P1).
6. **NLP Duplicate Detection Efficiency**:
   - Potential duplicates identified, confirmed duplicates, and engineering hours saved.

### 3. SLA Compliance Audit Report
- **Route**: `GET /api/reports/sla` (alias `/api/v1/reports/sla`)
- **Authorization**: `ADMIN`, `ANALYST`, `DEVELOPER`
- **Supported Formats**: `?format=pdf` (default) | `?format=csv`

#### Data Schema & Content Elements:
1. **Compliance Overview**:
   - Organization-wide SLA Compliance Rate (Target: $\ge 95\%$).
   - Total Breached Vulnerabilities and Warning Status Count.
2. **Breached Items Detail**:
   - Detailed audit listing of all breached tickets: Priority, Asset, Owner, Breach Timestamp, Overdue Duration.
3. **SLA Policy Matrix**:
   - P1: 24 Hours (Warning at 18h)
   - P2: 72 Hours (Warning at 54h)
   - P3: 168 Hours (Warning at 126h)
   - P4: 720 Hours (Warning at 540h)

## HTTP Response Headers & Streaming Mechanics

Every report endpoint implements HTTP streaming with standard headers:

| Format | Content-Type | Content-Disposition |
|---|---|---|
| **PDF** | `application/pdf` | `attachment; filename="FlawTrack_<Type>_<ID>_<Timestamp>.pdf"` |
| **CSV** | `text/csv` | `attachment; filename="FlawTrack_<Type>_<ID>_<Timestamp>.csv"` |
| **JSON** | `application/json` | Inline body |

## Frontend Integration

Reports are accessed in the frontend via:
1. **Vulnerability Detail Page** (`/vulnerabilities/:id`):
   - **Download PDF**: Generates the complete single-vulnerability report.
   - **Download JSON**: Exports structured technical data.
   - **Download CSV**: Downloads tabular ticket metrics.
2. **Dedicated Reports Center** (`/reports`):
   - Live KPI cards: Total Vulnerabilities, Open Items, SLA Compliance %, Breached Count.
   - Dynamic Filter Panel: Date Range, Priority Tier, Lifecycle Status.
   - One-click Executive Summary Export (PDF & CSV).
   - One-click SLA Compliance Report Export (PDF & CSV).
